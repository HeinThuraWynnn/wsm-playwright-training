# Specification

## Purpose
Turn a request into testable acceptance criteria.

## Activation
Requirements are new, ambiguous or changed.

## Inputs
Task request and discovery findings.

## Procedure
Define outcome, numbered observable criteria, scope exclusions and compatibility constraints. Ask only for information that materially blocks a correct implementation.

## Constraints
Do not expand user scope or invent approval.

## Outputs
Task specification with assumptions and unresolved questions.

## Completion
Criteria can be verified and material uncertainties are resolved or recorded.

## Failure handling
Record the missing input or failed check. Stop dependent work, retain existing files,
and resume at the interrupted lifecycle state once the blocker is resolved.
